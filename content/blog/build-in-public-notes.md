i don't have a grand "build in public" manifesto. i have a few rules that survived contact with real deadlines.

## ship before it's clever

clever is expensive. shipped is useful. most of my projects started as something i could demo in a day, then hardened into something people could actually use. the opposite order — architecture first, users never — is how demos die in folders.

## agents are products, not demos

an agent that works once in a notebook is a toy. an agent with a ui, logs, and a deploy url is a product. i care about the second kind. that means boring things: auth edges, rate limits, failure states, the "what happens when the model is wrong" path.

## keep a second brain, not a second backlog

obsidian (and similar) works when it's a place to *think*, not a graveyard of unchecked todos. if a note hasn't turned into a commit or a post in a month, it's compost — fine, but don't pretend it's a roadmap.

## the 3am rule

if i'm still building at 3am, either the idea is alive or i'm avoiding sleep. both happen. the useful filter: will tomorrow-me thank tonight-me for shipping this, or for stopping?

## writing here

this blog is part of the same loop — write when there's something concrete, deploy it with the site, move on. no cms. no draft graveyard. just files and a push.
